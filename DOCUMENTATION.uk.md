# Документація платформи для вивчення C++

Цей документ описує архітектуру, технологічний стек та структуру бази даних освітньої платформи для вивчення мови програмування C++.

## Технологічний стек

Проект побудований як монорепозиторій, що складається з клієнтської частини (frontend) та серверної частини (backend).

### Клієнтська частина (Client)
- **Framework**: [Next.js](https://nextjs.org/) (версія 16.1.6) - React-фреймворк для створення веб-додатків. Використовує App Router.
- **Мова програмування**: TypeScript.
- **UI бібліотека**: [Material UI (MUI)](https://mui.com/) - бібліотека компонентів для React.
- **Редактор коду**: [@monaco-editor/react](https://github.com/suren-atoyan/monaco-react) - компонент редактора VS Code для веб.
- **HTTP клієнт**: axios - для виконання запитів до API.
- **Анімації**: Framer Motion.
- **Управління станом**: Zustand (для легкого глобального стану) та React Context (для аутентифікації).

### Серверна частина (Server)
- **Framework**: [NestJS](https://nestjs.com/) - прогресивний Node.js фреймворк для створення ефективних та масштабованих серверних додатків.
- **Мова програмування**: TypeScript.
- **База даних**: PostgreSQL - потужна об'єктно-реляційна система баз даних.
- **ORM**: [Prisma](https://www.prisma.io/) - інструмент нового покоління для роботи з базами даних (TypeScript ORM).
- **Аутентифікація**: Passport.js + JWT (JSON Web Tokens).
- **Черги та Кеш**: Redis (використовується для BullMQ або кешування).
- **Безпека**: bcrypt (для хешування паролів).

## Як це працює

### Архітектура
1.  **Клієнт (Next.js)**: Відповідає за відображення інтерфейсу користувача. Сторінки рендеряться на сервері (SSR) або статично генеруються, а потім гідратуються на клієнті.
2.  **API (NestJS)**: Обробляє запити від клієнта. Забезпечує бізнес-логіку: реєстрацію, вхід, отримання курсів, уроків та перевірку коду.
3.  **База даних (PostgreSQL)**: Зберігає всю інформацію про користувачів, курси, уроки та прогрес.
4.  **Виконання коду**: Коли студент відправляє C++ код на перевірку:
    -   Клієнт відправляє код на сервер через API endpoint `/submissions`.
### Як працює виконання коду (Code Execution)

Система перевірки коду складається з наступних етапів:

1.  **Редактор коду (Frontend)**:
    -   Використовується **Monaco Editor** — той самий двигун, що і у VS Code.
    -   Він забезпечує підсвічування синтаксису C++, автодоповнення та нумерацію рядків прямо у браузері.
    -   Код користувача зберігається у стані React компонента.

2.  **Відправка на сервер**:
    -   При натисканні кнопки "Run & Check", клієнт відправляє `POST` запит на `/api/submissions/:lessonId`.
    -   Тіло запиту містить написаний студентом C++ код.

3.  **Обробка на сервері (Backend)**:
    -   Сервер (через `SubmissionsService`) створює запис у базі даних зі статусом `PENDING`.
    -   Код записується у тимчасовий файл (наприклад, `temp_123.cpp`).
    -   Сервер запускає процес компіляції за допомогою **g++** (GCC C++ Compiler).
    -   Якщо компіляція успішна, створюється виконуваний файл.
    -   Сервер запускає цей файл і перехоплює його стандартний вивід (`stdout`).
    -   *Примітка*: У повній версії цей процес має відбуватися в ізольованому Docker контейнері для безпеки. В поточній версії використовується локальний компілятор.

4.  **Перевірка результатів**:
    -   Вивід програми порівнюється з очікуваним результатом (Test Cases), який зберігається в базі даних для цього уроку.
    -   Якщо вивід співпадає, статус рішення змінюється на `PASSED`, якщо ні — `FAILED`, при помилці компіляції — `ERROR`.
    -   Результат повертається на клієнт і відображається користувачеві.

## Структура бази даних

База даних спроектована з використанням Prisma. Основні сутності:

### 1. User (Користувач)
Зберігає дані про зареєстрованих користувачів.
- `id`: Унікальний ідентифікатор (UUID).
- `email`: Електронна пошта (логін).
- `passwordHash`: Хеш пароля.
- `role`: Роль (STUDENT, ADMIN).
- `submissions`: Зв'язок з відправленими рішеннями.
- `progress`: Зв'язок з прогресом.

### 2. Course (Курс)
Навчальний курс (наприклад, "C++ Basics").
- `id`: UUID.
- `title`: Назва курсу.
- `slug`: Унікальний URL-ідентифікатор (наприклад, `cpp-basics`).
- `modules`: Курс складається з модулів.

### 3. Module (Модуль)
Група уроків в межах курсу.
- `id`: UUID.
- `title`: Назва модуля.
- `course`: Зв'язок з курсом.
- `lessons`: Список уроків у модулі.

### 4. Lesson (Урок)
Одиниця навчального контенту.
- `id`: UUID.
- `title`: Назва уроку.
- `type`: Тип уроку (`THEORY`, `PRACTICE`, `QUIZ`).
- `content`: Текст уроку (Markdown) або JSON для квізів.
- `initialCode`: Початковий код для практичних завдань.
- `submissions`: Зв'язок з рішеннями студентів.

### 5. Submission (Рішення)
Спроба вирішення практичного завдання.
- `id`: UUID.
- `code`: Код, написаний студентом.
- `status`: Статус (`PENDING`, `PASSED`, `FAILED`, `ERROR`).
- `output`: Вивід програми або помилка компіляції.
- `user`: Автор рішення.
- `lesson`: До якого уроку належить.

### 6. Progress (Прогрес)
Відстежує, які уроки користувач успішно завершив.
- `completed`: Чи завершено урок.
- `score`: Оцінка (для квізів).
- `user`: Студент.
- `lesson`: Урок.
